# PoseVLA Evaluation on RoboTwin

This guide explains how to evaluate a PoseVLA post-trained policy on the RoboTwin simulation platform.

RoboTwin evaluation usually runs in a separate simulation environment from PoseVLA training. You will typically need two environments:

- `posevla` or your PoseVLA training environment: for training and checkpoint generation.
- `RoboTwin` or your RoboTwin simulation environment: for simulation and evaluation.

## Environment Setup

### 1. Install RoboTwin Platform

Follow the official RoboTwin installation guide to create the RoboTwin simulation environment:

```text
https://robotwin-platform.github.io/doc/usage/robotwin-install.html
```

This creates a conda environment such as `RoboTwin` with the simulation dependencies required by RoboTwin.

### 2. Install Runtime Dependencies

Activate the RoboTwin environment and install the Python dependencies needed by PoseVLA inference. The exact versions should match your CUDA and RoboTwin setup. The reference RoboTwin evaluation environment used here is `RoboTwin_save`, which uses PyTorch 2.7.1 with CUDA 12.8:

```bash
conda activate RoboTwin
pip install torch==2.7.1 torchvision==0.22.1 \
    --index-url https://download.pytorch.org/whl/cu128
```

Then install the extra packages used by this PoseVLA deployment folder. The `requirements.txt` here is copied from the working `RoboTwin_save` environment:

```bash
cd /path/to/RoboTwin/policy/PoseVLA
pip install -r requirements.txt
```

If your RoboTwin environment cannot install all training dependencies cleanly, install only the inference-side packages needed to load PoseVLA, including `transformers`, `lerobot`, `safetensors`, `omegaconf`, and related runtime dependencies.

## Installation

### Deploy PoseVLA Policy to RoboTwin

Copy or symlink this folder into the RoboTwin policy directory:

```bash
ln -s /path/to/PoseVLA/robotwin/PoseVLA /path/to/RoboTwin/policy/PoseVLA
```

The expected structure is:

```text
RoboTwin/
├── policy/
│   ├── PoseVLA/
│   │   ├── deploy_policy.py
│   │   ├── deploy_policy.yml
│   │   ├── eval_policy.py
│   │   ├── model.py
│   │   ├── run_auto_eval_posevla.sh
│   │   └── README.md
│   └── ... other policies
├── script/
│   └── eval_policy.py
└── ... other RoboTwin files
```

Replace RoboTwin's default evaluation entry with the PoseVLA-compatible one:

```bash
cp /path/to/RoboTwin/policy/PoseVLA/eval_policy.py /path/to/RoboTwin/script/eval_policy.py
```

For parallel evaluation, copy `run_auto_eval_posevla.sh` to the RoboTwin root manually:

```bash
cp /path/to/RoboTwin/policy/PoseVLA/run_auto_eval_posevla.sh /path/to/RoboTwin/run_auto_eval_posevla.sh
chmod +x /path/to/RoboTwin/run_auto_eval_posevla.sh
```

## Configuration

Edit `deploy_policy.yml`:

```yaml
policy_name: policy.PoseVLA
task_name: beat_block_hammer
task_config: demo_randomized
ckpt_setting: default
seed: 10000
instruction_type: unseen
policy_conda_env: 0
checkpoint_id: 19999
ckpt_dir_name: align_bs12_1_robotwin # saved ckpt path
checkpoint_path:  # optional; if empty, use ckpt/<ckpt_dir_name>/<checkpoint_id>/model
action_type: eep
norm_path: /path/to/global_stats_output_eep/qpos_mean_std_online.pkl
left_arm_dim: 8
right_arm_dim: 8
port: 8081
```

Important fields:

- `policy_name`: must match the RoboTwin policy folder, usually `policy.PoseVLA`.
- `task_name`: the RoboTwin task to evaluate.
- `task_config`: RoboTwin task config, such as `demo_randomized` or `demo_clean`.
- `checkpoint_path`: direct path to a saved PoseVLA model directory, for example `.../ckpt/<exp>/<step>/model`.
- `ckpt_dir_name` and `checkpoint_id`: fallback checkpoint lookup when `checkpoint_path` is empty.
- `action_type`: use `eep` for the current Robotwin PoseVLA setup.
- `norm_path`: statistics file generated by `scripts/stats/norm_robotwin.py`.
- `left_arm_dim` and `right_arm_dim`: use `8` and `8` for 16-dim EEP actions.

If `checkpoint_path` is empty, `model.py` falls back to:

```text
<PoseVLA repo>/ckpt/<ckpt_dir_name>/<checkpoint_id>/model
```

`norm_path` must correspond to the same processed Robotwin data and action type used during training. For EEP training, it should contain `action_mean`, `action_std`, `eep_mean`, and `eep_std`.

## Running Evaluation

Run RoboTwin evaluation using the normal RoboTwin entry point, with this policy folder selected. For example:

```bash
cd /path/to/RoboTwin
conda activate RoboTwin
python script/eval_policy.py --config policy/PoseVLA/robotwin/PoseVLA/deploy_policy.yml
```

The exact command may differ depending on the RoboTwin version and your local evaluation script. The key requirement is that RoboTwin loads `policy/PoseVLA/deploy_policy.yml` and imports `policy/PoseVLA/deploy_policy.py`.

For parallel evaluation, edit `run_auto_eval_posevla.sh` first: set `GPU_IDS`, `CHECKPOINT_ID`, `CKPT_DIR_NAME`, `TASK_CONFIG`, `SEED`, and the `TASKS` list as needed. Then run it from the RoboTwin root:

```bash
cd /path/to/RoboTwin
bash run_auto_eval_posevla.sh
```

The script dispatches tasks across `GPU_IDS` in parallel, writes one log per task, and generates a summary after all tasks finish.

## Viewing Results

`run_auto_eval_posevla.sh` writes logs to:

```text
RoboTwin/eval_result/auto_eval_YYYYMMDD_HHMMSS/
```

Each task has its own `<task>.log`. The final summary is saved as:

```text
RoboTwin/eval_result/auto_eval_YYYYMMDD_HHMMSS/evaluation_summary.txt
```

Open `evaluation_summary.txt` to check success, failure, total task count, and success rate.

## File Overview

- `deploy_policy.py`: converts RoboTwin observations into PoseVLA batch format, normalizes EEP/qpos state, denormalizes predicted actions, and sends actions back to RoboTwin.
- `model.py`: loads the PoseVLA checkpoint and runs chunked inference. For EEP, it keeps the 16-dim action output used by Robotwin.
- `deploy_policy.yml`: RoboTwin-side policy config.
- `eval_policy.py`: PoseVLA-compatible RoboTwin evaluation entry. Copy it to `RoboTwin/script/eval_policy.py`.
- `run_auto_eval_posevla.sh`: parallel RoboTwin evaluation launcher. Copy it to the RoboTwin root before running.
